## 缺陷修复

### 多标签页雷达扫描接受较晚返回的旧数据

`performUpdate()`（`src/020-core-friend-radar.js:1219`）在第一个请求之前读取状态，记下 `latestSnapshot` 的序列化结果。提交时在锁内重新读取，快照与扫描开始时不一致则返回 `CONCURRENT_MODIFICATION`（原因码 `SNAPSHOT_CHANGED_DURING_SCAN`），不做差分、不写入。原有的 `checkScanFreshness()`、账号校验、状态锁和写后读回均保留。

与粉丝扫描的做法有一处有意的差别：这里只比较快照，不比较整串存储值。雷达事件带已读标记，“全部标为已读”会改写整串存储；按整串比较会让扫描期间的标记已读、或后台自动更新期间另一标签页的标记已读导致扫描作废。事件仍按锁内读到的最新状态合并。请审查这一取舍是否成立。

附带效果：状态无法读取时在发请求前失败，且不触发 `beforeFirstRequest`，自动更新不会记下一次没有发生的尝试。

### 雷达状态损坏时无法通过备份恢复

- 首页 `showToolkitHome()`（`src/120-settings-launcher-startup.js:591`）不再在雷达状态读取失败时整页返回。雷达卡片显示错误，其余模块和“恢复备份”保持可用。读取失败时不更新未读角标。
- `restoreBackup()`（`src/100-restore-export.js:800`）在 `loadState()` 失败时改读原始值令牌。令牌可读且为字符串时继续，并以该字节串作为预期值；令牌读取抛错、值为非字符串或不存在时仍然拒绝。
- `showRestorePreview()` 在当前数据无法读取时显示明确提示，说明可能是损坏，也可能由更新版本的脚本写入；当前事件数和快照记录数显示为“无法读取（将被备份内容替换）”，“先备份当前数据”按钮禁用。
- `restoreValidatedBackup()` 的锁内校验由“当前状态必须有效且原始值一致”改为“原始值必须与预览时一致”。对有效状态这两者等价；对损坏状态，只有预览过的那串字节可以被替换。
- `showAutoUpdateSettings()`（`src/110-overview-auto-update.js:365`）在雷达或粉丝状态读取失败时不再整页失败，对应分区显示错误，“上次成功更新”显示“无法读取”，间隔设置和外观设置保持可用。

没有改变的行为：扫描不会覆盖损坏的状态；备份的版本、格式、账号和各模块校验不变；回滚仍按原始字节写回，因此后续模块失败时会回到损坏前的那串字节。

### 请求缺少期限，粉丝取消无法中断等待

`fetchScanPage()`（`src/020-core-friend-radar.js:448`）为关系雷达和粉丝的读取请求设置 30 秒期限，定时器在正文读取结束后才清除。超时返回 `NETWORK_ERROR` 加原因码 `REQUEST_TIMEOUT`，两处失败文案都有对应说明。

粉丝扫描的“取消”通过 `AbortController` 中断当前请求。扫描循环在检查请求结果之前先检查取消标志，被中断的请求报告为 `FOLLOWER_SCAN_CANCELLED` 而不是网络失败。取消只作用于扫描阶段。

30 秒是本轮选定的数值，没有依据真实接口的响应时间分布。粉丝移除 POST（`src/070-follower-hygiene-removal.js`）没有改动：中断它无法判断微博端是否已执行。

### 扫描结束替换用户后来打开的面板

`updateNow()` 和 `updateFollowersNow()`（`src/060-ui-updates-followers.js:612`、`:847`）在显示进度后记下 `panelRoot`。完成时只有当前面板仍是该进度面板才显示结果；否则只调用 `setLauncherStatus()`，在启动器上显示结果约 5 秒。

### 通用弹窗的键盘和读屏行为

`showPanel()`（`src/060-ui-updates-followers.js:110`）增加 `role="dialog"`、`aria-modal`、`aria-labelledby` 和 `tabindex="-1"`，打开时把焦点移入面板。`closePanel()` 在真正关闭时把焦点还给打开第一个面板的元素；面板互相替换时不回弹。

`handlePanelKeydown()`（`:68`）处理 Tab 循环和 Esc。Esc 在以下情况不关闭面板：输入法组词中（`isComposing` 或 `keyCode === 229`）、事件目标是文本输入控件、面板内的友人档案编辑器有未保存内容、`followerRemovalInFlight` 为真。监听器挂在遮罩根节点上。

面板打开时总是移入焦点。启动时自动弹出的更新通知改为在页面焦点位于文本输入控件内时不弹出，留到下次页面加载，且不记为已读（`maybeAutoShowBundledChangelog()`）。

## 针对首轮审查意见的后续修改

- 恢复备份：确认后到事务结束之间面板被锁定。第二轮审查指出最初的实现只禁用了头部按钮和 Esc，脚本菜单仍能替换面板并清除锁。现在锁在 `closePanel()` 和 `showPanel()` 内部执行：锁定时 `closePanel()` 直接返回，`showPanel()` 返回一个不挂载的正文节点，因此按钮、Esc、脚本菜单和任何迟到的回调都无法移除或替换被锁的面板。头部按钮的禁用只用于显示状态。事务抛错时按 `RESTORE_STATE_UNCERTAIN` 处理。`tests/friend-notes-ui.test.js` 增加了锁定面板不被关闭或替换的检查。
- 浏览体验中“显示主页小档案”的说明补回了启用后会记录访问的告知：“显示历史昵称等本地资料，并在本浏览器记录访问次数和上次访问时间。”
- 粉丝扫描：`performFollowerUpdate()` 在取得状态锁之后、第一次写入之前再检查一次取消，等待锁期间点击取消会得到 `FOLLOWER_SCAN_CANCELLED` 且不写入。
- `addLine()` 的分组识别改用 `classList.contains()`。

粉丝取消的锁内检查由第二轮审查复验通过，本方没有单独执行；恢复锁定有上述永久检查，但完整的恢复确认流程没有在模拟页面中走过；通知延后、打开时移入焦点和事实行分组在模拟页面中执行过。

恢复期间的锁定没有超时：如果另一个标签页长时间持有状态锁，预览面板会一直无法关闭，只能刷新页面。

### 较小的修复

- 浏览体验页签（`src/120-settings-launcher-startup.js:10` 起）支持左右方向键、Home、End，只有选中的页签在 Tab 顺序内。
- 两处计步器入口改为无参包装，click Event 不再被当作提示文字。
- 粉丝扫描的取消按钮放入操作区容器。

## UI 改动

以下均在上一轮重设计的基础上进行。

- **尺度**：圆角归并为 `--wfr-radius-s/m/l`（6 / 8 / 12px）。字号归并为 12 / 13 / 14 / 16px，较上一轮整体加大 1px。字重 550 和 650 改为 500 和 600。浅色 `--wfr-muted` 由 `#71746f` 调深为 `#676a65`。等宽字体栈在 `monospace` 前加入 `system-ui`。吸底栏阴影改为主题变量 `--wfr-bar-shadow`。
- **首页**：去掉眉题和大标题，保留一行说明。
- **装饰**：删除面板标题和启动器前的斜线装饰。
- **面板尺寸**：`showPanel()` 新增第三个参数。首页、带返回按钮的页面，以及在这类面板打开期间替换它的面板，使用固定高度 `min(640px, 视口高度减边距)`；独立弹出的面板按内容高度显示。
- **事实行**：`addLine()` 把连续的行收进同一个 `.wfr-kv-group` 容器，标签不再带冒号，并返回数值节点。面板正文中的分组显示为带边框的列表；事件卡片和首页卡片内的分组不加边框。扫描进度的行使用同一结构。
- **分区与状态**：正文中第二个及之后的 `h3` 上方有分隔线。直接位于正文下的成功和失败提示显示为带左边线的提示条。空状态使用 `.wfr-empty` 虚线框。未读事件卡片标题前有圆点。标签加下拉框的表单行改为 flex 对齐。
- **层叠修正**：`.wfr-note-link` 去掉旧的字号和行高并补悬停样式；启动器悬停选择器改为 `:hover:enabled`，恢复使用自己的变量。
- **私信导出控件**：保留上一轮的圆角、焦点环和状态样式，去掉跟随系统深色的规则，固定为浅色。

## 界面打磨

- **失败原因码**：`failureText()` 和 `followerFailureText()` 不再把原因码拼进句子。`appendFailureCode()` 在失败提示下方单独显示一行“错误代码 XXX”。恢复失败和请求超时已有专门文案，不显示这一行。
- **进度指示**：两个扫描进度面板在说明文字下方增加 `.wfr-progress` 指示条，使用 CSS 动画；`prefers-reduced-motion` 下为静态。没有增加 `aria-live`。
- **短分组**：直接位于面板正文下、且只有一行或两行的 `.wfr-kv-group` 改为单行排布。使用 `:has()` 选择器，不支持的浏览器保持原来的逐行列表。事件卡片和首页卡片内的分组不受影响。
- **书签形状**：`.wfr-feed-note-has` 的图标遮罩改为实心路径，有无档案不再只靠颜色区分。

## 未覆盖范围

- 真实登录微博页面中的任何验收，包括注入、样式隔离和私信会话页。
- 粉丝体检（含吸底栏）、恢复预览、友人档案详情和编辑器、信息流浮卡、主页小档案在新样式下的外观。

## 已知限制和未做事项

- 用户离开进度面板后，手动更新的失败只在启动器上显示约 5 秒，之后没有可回看的位置。自动更新有结果记录，手动更新没有。
- 关闭进度面板后没有返回进度的入口，再次点击更新只会得到 `UPDATE_ALREADY_RUNNING`。粉丝扫描此时也无法取消，只能等它结束或超时。
- 友人档案草稿的退出保护没有改动。关闭按钮和返回按钮仍直接移除编辑界面；本轮只让 Esc 和后台任务完成不再触发这条路径。
- 进度面板没有 `aria-live`。
- 事件列表全量渲染和友人档案重复派生的规模问题没有处理。
- 书签布局测试的旧显示假设没有核对。
- 版本号仍为 `0.10.0`，与已发布标签相同。分发前需要升版本号并补更新记录。

## 建议重点审查的内容

1. `performUpdate()` 只比较快照而不比较整串存储值，是否存在仍能写入旧数据的路径，尤其是备份恢复与扫描交错时。
2. `restoreValidatedBackup()` 的锁内校验从“状态有效”放宽为“字节一致”，是否在任何路径上削弱了原有保护；`currentFriendRadarRestoreToken()` 对不存在、非字符串和读取抛错三种情况的区分是否完整。
3. `fetchScanPage()` 的定时器和监听器是否在所有结束路径上清理；取消与超时同时发生时的结果分类。

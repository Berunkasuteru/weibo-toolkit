# Weibo Toolkit v0.10.2：UI 与批量移除审查记录

日期：2026 年 10 月 6 日。本文记录 `v0.10.1` 之后、纳入 `v0.10.2` 的改动和审查结果。`v0.10.1` 的 GitHub Release 已撤下，原标签与代码历史保留。

本文只记录事实、验证范围和已知限制。脚本版本、内置更新记录和发布说明已同步至 `0.10.2`；正式发布状态以 GitHub Release 为准。

## 改动来源

`v0.10.1` 推送后，在真实微博页面上发现了三处界面问题，并提出了两项功能要求和一项趣味性改动。本轮改动全部针对这些反馈。

## 审查范围

本轮按 `AGENTS.md` 审查工作副本改动；以下保留最初的五个审查问题，并汇总后续修复与验证。

| 文件 | 改动 |
| --- | --- |
| `src/070-follower-hygiene-removal.js` | 批量上限 200、跨页保留选择；退出锁与忙碌选择保护；旧确认作废和最终名单复验；操作栏高度预留与监听清理 |
| `src/120-settings-launcher-startup.js` | 面板高度、吸底操作栏、事件卡片、事实分组、进度指示及窄窗口适配 |

| `src/000-preamble-pm-core.js`、`src/020-core-friend-radar.js`、`docs/releases/v0.10.2.md` | 版本号、内置更新记录和发布说明 |
| `tests/follower-removal-ui.test.js` | 批量锁定、停止、旧确认作废和最终状态核对的回归检查 |

## 一、批量移除粉丝（行为变更，请优先审查）

这是本轮唯一改变产品安全边界的地方，由用户明确要求并在两个选项中做了选择：上限 200 个（未选 500 或不设上限），选择方式为跨页保留（未选“选择全部筛选结果”）。

具体改动：

- `FOLLOWER_BATCH_MAX_SELECTION` 由 `50` 改为 `200`，其上方的注释同步更新。
- “上一页”“下一页”的处理函数不再调用 `clearSelection()`。修改筛选条件仍然清空选择（`renderResults(true)` 路径未变）。
- 新增 `currentMatches`，在 `renderResults()` 中保存当前筛选条件下的全部匹配结果。
- `selectedVisibleRecords()` 改名为 `selectedRecords()`，从 `currentMatches` 而不是当前页取已选记录。移除顺序为匹配结果的顺序。

没有改变的行为：每次都需确认；确认框列出全部已选账号；逐个顺序发送；每次成功后约等待 3 秒；不自动重试；失败、结果无法确认或用户停止后不再发送；批量进行中不能翻页。没有“选择全部筛选结果”，没有后台自动移除。`startFollowerRemovalBatch()` 及其以下的执行路径没有改动。

请审查：

1. 选择跨页后，是否存在已选账号不在 `currentMatches` 中的路径。目前的依据是：只有筛选条件变化会改变匹配集合，而该路径会清空选择。快照在体检面板打开期间被更新时是否仍成立，请核对。
2. `refreshCard()` 对不在当前页的账号直接返回。批量执行期间，其他页的账号的成功、失败和不确定状态是否都正确记入 `successfullyRemovedUids`、`uncertainRemovalUids` 和 `removalMessages`，翻到那一页时是否正确显示。
3. 单个移除和批量结果回调中的 `selectedUids.delete()` 在跨页选择下是否仍然正确。
4. 代码和文档中是否还有“当前页”“五十”“50 个”之类与新行为不符的表述。`selectCurrentPage()` 上方的注释仍写着“current-page only”，它描述的是该按钮的作用范围，没有改。
5. 200 个一批约需 10 分钟。微博对连续移除的限制无法从本地判断，本轮没有发送过任何真实移除请求。

## 二、面板高度

`v0.10.1` 中，首页和带返回按钮的面板固定为 640px 高。真实页面上，粉丝体检这类长列表只能在很小的区域里滚动。

现在 `.wfr-panel-fixed` 为 `min-height: min(640px, 视口高度减边距)`，高度随内容增长，上限仍是 `.wfr-panel` 的 `max-height`。同时 `align-self: start`，面板贴着遮罩上沿对齐，页面间切换时标题栏位置不变，只有下沿伸缩。独立弹出的面板不带该类，仍居中并按内容高度显示。

## 三、粉丝体检的吸底操作栏

`v0.10.1` 中，操作栏吸附在正文滚动区内边距之上，下方会露出一条卡片内容。

体检面板的正文现在带 `wfr-body-flush` 类：正文下内边距为 0，操作栏左右用负外边距铺满，只保留上边线，没有圆角。结果列表加了下外边距，滚到末尾时最后一张卡片不被遮住。680px 以下的内边距数值在媒体查询中另行给出。

## 四、其余样式改动

- **事件卡片行**：标签列由 `5em` 改为 `3em`，列间距由 12px 改为 10px。
- **事实分组**：直接位于面板正文下的 `.wfr-kv-group` 由“标签居左、数值居右”的列表改为网格卡片，每项为标签在上、数值在下的方块，`repeat(auto-fill, minmax(min(190px, 100%), 1fr))`，最小宽度受容器限制。上一版针对一两行分组的 `:has()` 单行排布规则已删除。事件卡片内、首页卡片内和批量结果汇总中的分组不受影响。
- **进度指示**：`.wfr-progress` 由滑动细线改为吃豆人动画。背景是一排圆点，`::before` 是来回移动并开合的吃豆人，`::after` 是遮住已经过圆点的色块。纯 CSS，没有新增 DOM 节点。`prefers-reduced-motion` 下两个伪元素都不播放动画。吃豆人颜色固定为 `#e8b004`，没有走主题变量。

- 请求挂起时打开雷达进度页，把动画定格在 1.5 秒和 3.75 秒各截图一次：去程吃豆人朝右，左侧圆点已被遮住；回程朝左，右侧圆点已被遮住。
- 关系概览和自动更新设置两页的网格卡片在深色主题下截图核对过。

## 未覆盖范围

- 真实微博页面上的任何验收。本轮的三处界面问题都是在真实页面上发现的，修改后没有回到真实页面复核。
- 真实微博中的批量移除执行与完整恢复流程。模拟状态不能代替微博宿主 DOM、样式和网络行为验收。
- Firefox 等全面跨浏览器验收，以及修复后完整 245 个组合的再次运行。
- 私信导出控件的真实宿主页面及极窄窗口适配；本轮暂缓这部分改动。
- 吃豆人开合和掉头的连续观感，截图无法体现。

## 已知限制

- 从短页面进入长页面时，面板下沿会向下伸长。最小高度为 640px 与视口可用高度的较小值。
- 批量移除期间页面需保持打开。POST 仍没有请求期限；请求挂起时退出锁会保持，停止只能阻止后续请求，不能撤回已经发送的操作。
- 私信导出控件在极窄模拟容器中向左越界，待真实私信页验收时处理。

本记录不把模拟验收表述为真实微博验收。发布说明中的限制与本记录保持一致。

# Weibo Toolkit

一个本地优先的微博桌面网页版用户脚本工具箱：给熟悉的人留下私人备注，记录接口可见的关系变化，查看粉丝快照，导出当前私信会话，并按需改善浏览体验。

[Greasy Fork 安装](https://greasyfork.org/zh-CN/scripts/591269-weibo-toolkit-friend-radar) · [GitHub 最新版本](https://github.com/Berunkasuteru/weibo-toolkit/releases/latest) · [反馈问题](https://github.com/Berunkasuteru/weibo-toolkit/issues)

## v0.10.0 新增内容

**友人档案现在可以在信息流里用了。** 为一个账号写下“去年摄影展认识的阿岚，喜欢拍海边”，再添加“摄影”“熟人”等标签；档案按稳定 UID 保存，对方改名后仍然属于同一个人。

- 工具箱里的 **友人档案** 可浏览、搜索、按标签筛选和编辑。
- 可选在他人主页显示档案，或在首页与“最新微博”的作者旁显示一个小书签。
- 点击书签先查看，主动点击“添加备注与标签”或“编辑”才进入表单；没有实际修改时可以直接关闭。
- **Backup v3** 一并备份手写备注与标签；旧 v1/v2 备份仍能恢复，且保留现有友人档案。

这两个页面选项默认关闭。安装或升级后，在 **工具箱 → 浏览体验 → 增强** 中按需开启。完整更新说明见 [v0.10.0](docs/releases/v0.10.0.md)。

产品界面以中文为主。除“移除粉丝”外，主要功能均为只读或仅修改浏览器本地数据；所有页面增强和使用统计默认关闭。

## 先看重要边界

- **关系雷达**只能记录微博接口当前返回的可见关注结果，不是完整社交关系档案。
- “从可见关注列表消失”只表示接口不再返回该账号，**不等于**取关、拉黑、销号或任何确定原因。
- **粉丝快照**同样只是 API 可见结果，微博可能过滤部分粉丝，不能保证完整。
- **私信导出**只包含接口在导出时实际返回的当前普通一对一会话内容，不是账号级完整私信备份。
- **友人档案**里的备注和标签完全由你手写，只保存在当前浏览器；Toolkit 不会替你生成备注、标签或评价，也不会为它新增任何微博请求。
- **浏览体验中的页面功能、主页小档案、主页和信息流里的友人档案、微博计步器全部默认关闭**，升级后不会自动改变微博页面外观或开始记录使用统计。
- **移除粉丝**是主要功能中唯一会修改真实微博关系的操作；每次都需要确认，并受顺序、限速和遇错停止规则约束。
- 当前面向桌面微博网页；Mobile Safari、iPhone 和 iPad 微博网页暂不支持。

## 安装与首次使用

目标页面：

```text
https://weibo.com/
```

典型环境：桌面 Chrome、Edge、Firefox 或 Safari，加 Tampermonkey 或兼容的用户脚本管理器。当前实际浏览器验证覆盖 Tampermonkey on Chrome、Edge、Vivaldi 和 Firefox；未验证的平台不作额外兼容性承诺。

1. 安装 Tampermonkey 或兼容用户脚本管理器。
2. 从 [Greasy Fork](https://greasyfork.org/zh-CN/scripts/591269-weibo-toolkit-friend-radar) 安装 **Weibo Toolkit - Friend Radar**，或下载 [GitHub Release](https://github.com/Berunkasuteru/weibo-toolkit/releases/latest) 中的 `weibo-toolkit.user.js` 手动安装为一个用户脚本。
3. 登录并打开 `https://weibo.com/`。
4. 刷新页面。
5. 页面右下角应出现 **Weibo Toolkit** 启动器。

用户脚本菜单中还保留一个 **Weibo Toolkit：打开工具箱** 入口，作为启动器不可用时的后备方式。

### 没有看到启动器？

如果 Tampermonkey 显示当前页面没有运行脚本，请依次确认：

- 使用的是桌面浏览器，而不是 iPhone/iPad/Mobile Safari；
- 地址确实是 `https://weibo.com/`，私信导出页面则是微博当前的 `https://api.weibo.com/chat...`；
- 用户脚本已启用；
- 浏览器已允许 Tampermonkey 访问该站点；
- 修改用户脚本后已经保存并刷新微博页面。

手动安装的副本不会自动获得用户脚本版本更新。升级时应在原有脚本上替换内容并保存，不要删除后另建第二份脚本，以免本地存储变得不可访问。

## 主要功能

### 关系雷达

关系雷达手动读取 API 可见关注列表，以稳定 UID 保存成功快照，并比较后续成功快照。它可以记录：

- 账号出现在可见关注列表；
- 账号从可见关注列表消失；
- 可见列表中的账号开始关注你或停止关注你；
- 昵称变化。

第一次成功更新只建立基线，不生成历史事件。更新时会显示当前页、请求数和已验证记录数；接口报告总数只原样显示，不被当作精确进度。

事件详情保留中性的前后状态。个人关系时间线按 UID 归并、按时间倒序显示；同名账号不会合并，改名也不会切断同一 UID 的时间线。事件列表可按昵称或 UID 搜索，并可导出 UTF-8 CSV 或 Markdown。导出只包含 Toolkit 已观察并保存的事件。

“开始关注你 / 停止关注你”只覆盖同时存在于 API 可见关注列表中的账号；工具不会为此抓取完整粉丝列表。

### 粉丝快照与粉丝变化

**更新粉丝快照**读取微博 API 当前返回的粉丝结果，并以稳定 UID 保存到当前浏览器。第一次成功更新只建立快照；后续更新可记录：

- 出现在 API 可见粉丝结果；
- 从 API 可见粉丝结果消失。

这些描述不推断取关、拉黑、销号等原因。粉丝变化事件可以单条清除或确认后全部清空；清除事件不会修改微博关系，也不会删除粉丝快照。

### 粉丝体检

**粉丝体检**只在最新成功粉丝快照上进行本地筛选，本身不向微博发送请求。可使用的事实条件包括：

- 你没有关注该账号；
- API 显示的公开微博数、粉丝数或关注数不高于指定值；
- API 显示为未认证；
- 注册日期晚于指定日期；
- 关注来源属于推荐、个人主页、搜索、其他或未知来源。

未知值不会匹配数值阈值。结果每页 50 条；换页或修改筛选会清空当前选择。工具不提供“选择全部结果”或自动清理，也不会给账号贴“机器人”“僵尸粉”等判断标签。

### 移除粉丝

粉丝体检结果支持单个 **移除粉丝**，也支持对当前页手动选择的账号执行 **移除所选粉丝**。两者都会修改真实微博关系，移除后相关账号将不再是你的粉丝，Toolkit 无法自动撤销。

安全边界：

- 每批最多 50 个账号，且只能来自当前页；
- 每次操作前明确确认；
- 请求逐个顺序发送，不并发；
- 每个已验证成功后约等待 3 秒；
- 不自动重试；
- 一旦失败、结果无法确认或用户停止，剩余请求不再发送；
- 没有“移除全部筛选结果”或后台自动移除。

成功移除不会伪造粉丝快照变化。需要再次更新粉丝快照，才能看到接口当前返回的结果。

### 自动更新

关系雷达和粉丝快照分别提供可选自动更新，默认均为 **关闭**。可选间隔为 24、48、72 小时、7 天或 15 天。

自动更新只在打开或刷新桌面微博页面后检查一次，不是浏览器后台服务，不会轮询，也永远不会自动移除粉丝。失败不会进入连续重试。浏览器无法提供可靠跨标签锁时，自动更新会安全跳过。

### 浏览体验

所有页面选项默认关闭，且不进入备份。面板分为 **信息流 / 增强 / 净化** 三个页签：

- **首页优先进入最新微博**：每个标签页首次符合条件进入首页时，可跳转一次到微博原生“最新微博”；之后用户可切回“全部关注”并停留。
- **隐藏信息流中的推广内容**：基础过滤仍保持保守，只隐藏首页和微博原生“最新微博”中由专用语义标签明确标记为“荐读”的卡片，并尽量保持虚拟信息流的布局稳定；不扫描普通微博正文或昵称关键词，也不承诺完整去广告。
- **使用强力规则（可能误伤）**：默认关闭，且只在启用基础过滤后生效；可额外尝试识别专用语义标签中的“推荐”“广告”“推广”、TipsAd 风格的明确广告模块和部分强推荐信号，可能存在误伤，也不承诺完整去广告。
- **自动展开原创长微博**：默认关闭；可在首页、微博原生“最新微博”和数字 UID 个人主页中，在停止滚动并稳定阅读当前原创长微博时自动展开；转发微博保持折叠，以减少滚动过程中的突兀位移。原生展开可能触发微博自身的正文加载，Toolkit 不直接请求长微博全文。
- **隐藏微博热搜**、**隐藏整个右侧栏**、**隐藏顶部推荐入口**、**隐藏顶部视频入口**：彼此独立，可随时恢复。

### 主页小档案

可选 **显示主页小档案** 默认关闭，只作用于其他用户的 `/u/<UID>` 主页，不作用于当前账号自己的主页。

它只复用当前浏览器里已有的关系雷达、粉丝快照和事件数据，可能显示：

- 历史昵称（仅 Toolkit 本地实际记录过的名称）；
- 最近一条本地关系记录；
- 能由现有持久数据证明的最早本地记录；
- 上次访问；
- 当前浏览器中的累计访问次数。

历史昵称通过紧凑的语义化浮层查看。主页小档案不新增个人主页 API 请求，不声称“完整曾用名”“真实关注日期”或“完整关系历史”。访问足迹仅包含目标 UID、次数和最后访问时间，不进入备份。

### 友人档案

友人档案让你为微博上的某个人留下自己的记忆：一段私人备注和若干自定义标签。档案以对方的稳定 UID 绑定，昵称不是主键，所以对方改名后备注仍在，同名的两个账号也不会混在一起。

- **工具箱入口始终可用**：Toolkit Home 的 **友人档案** 可浏览全部已保存档案，按昵称、Toolkit 记录过的历史昵称、UID、备注或标签搜索，按标签筛选，打开对应主页，编辑或删除档案，并进入已有的关系时间线。列表每次显示 20 条，可继续加载。
- **在任意他人主页上添加**：打开对方的 `/u/<UID>` 主页后，从工具箱的友人档案里选择“为当前主页写档案”即可，不需要先有关系雷达或粉丝快照。
- **可选的主页显示**：“浏览体验 → 增强”中的 **在主页显示友人档案** 默认关闭。开启后，其他用户的 `/u/<UID>` 主页会出现一个紧凑面板，可直接查看、添加、编辑和删除备注与标签。它不记录访问，不依赖也不开启主页小档案或微博计步器。
- **可选的信息流显示**：“浏览体验 → 增强”中的 **在信息流显示友人档案** 默认关闭，见下文。

手写内容与工具观察分开呈现：

- **你写的**：备注和标签，以及它们的创建、修改时间。
- **Toolkit 观察到的**：最近记录昵称（附记录时间）、本地记录过的其他昵称、最近关系记录和最早本地记录。它们每次都从关系雷达、粉丝快照及其事件现算，不会复制进档案；相关记录被清除或被恢复替换后，搜索和显示也随之消失。没有任何本地昵称记录时，只显示 UID。主页小档案已开启时，面板不再重复显示这些信息。

限制与提示：

- 备注最多 1000 个字；每个档案最多 12 个标签，每个标签最多 20 个字；每个账号最多 2000 条档案。空白备注和空标签不会被保存。
- 备注和标签按纯文本保存和显示。
- 两个标签页同时编辑同一个档案时，后保存的一方会看到冲突提示和对方已保存的内容，自己的输入保留在编辑框里，由你决定采用哪一个；不同的人的档案可以同时保存，互不覆盖。
- 无法可靠识别当前登录账号或目标 UID、浏览器无法提供跨标签页锁、或本地档案数据无法读取时，保存会被明确禁用或失败，不会猜测身份，也不会重置已有数据。保存失败时输入不会丢失。
- 在工具箱里保存或删除某人的档案后，同一标签页中已打开的该主页面板会随之更新；如果面板里正有未保存的输入，输入会保留，并在保存时照常进行冲突检查。
- 使用输入法组词时按下的回车只用于选字，不会添加标签或触发保存。
- 删除档案需要确认，且只删除手写内容，不影响关系事件。
- 搜索只覆盖已保存档案和上述本地记录，不包含微博正文、私信或访问足迹，也不会为搜索发起请求。

#### 信息流中的友人档案

开启 **在信息流显示友人档案** 后，微博首页和原生“最新微博”中，能可靠识别作者的卡片会显示一个轻量书签，优先位于外层作者昵称旁；无法确定昵称插入点时位于发布时间旁。

- 没有档案时，书签低调显示；已有档案时使用强调色。
- 悬停可查看操作提示，点击后先查看档案。新建或编辑需要主动点击相应按钮。
- 备注、标签与 Toolkit 实际记录过的昵称在卡片里查看，不铺在信息流标题行。旧昵称只表示本地有过这样的记录，不代表已确认的改名，也不是完整的昵称历史；页面当前昵称不会被自动保存。

入口不改动微博原生的昵称、时间和来源文字，支持昵称链接以及无评语纯转发使用的 `usercard` 昵称节点。

点击入口时，Toolkit 会按页面当时的内容重新确认这条微博的作者；如果这个位置已经换成了别人的微博、证据出现矛盾或微博已被移除，就不会打开原来那个人的档案。

点击入口会在作者旁打开一张友人卡片，可以查看备注和标签、查看 Toolkit 的本地观察记录、新建、编辑或删除档案，并打开对方主页或工具箱里的完整档案。卡片使用与主页面板相同的编辑器，保存、冲突提示、删除确认和输入法保护的行为一致。备注正文不会直接铺在信息流里，只有点开卡片才显示。一次只会打开一张卡片。卡片始终留在窗口可见范围内：下方放不下就放到上方，上下都放不下就贴在窗口内并可能盖住入口；内容比窗口高时在卡片内部滚动，“关闭”始终可见。

这个选项是独立的：不需要开启隐藏推广、自动展开、主页小档案、主页友人档案或计步器，也不会替你开启它们。它只读取本地数据，不保存微博正文、浏览记录、作者访问统计或页面昵称，不新增微博请求，也不进入备份。

作者身份只按 UID 绑定，并且必须能从页面上证明：

- 依据是外层微博标题区里这条微博自己的链接（`/<UID>/<微博 ID>`）；同一标题区里的 `/u/<UID>` 作者链接必须与它一致。
- 证据缺失或互相矛盾时，这条微博不显示入口。Toolkit 不会用昵称去匹配 UID，不会把微博 ID 当成 UID，也不会为了识别作者发请求。
- 转发微博只识别外层的转发者；被转发的原作者、正文里提到的人和评论里的账号都不参与。
- 作者链接是个性域名时，仍可按 UID 显示入口，但没有昵称提示。
- 自己发的微博不显示入口；被“隐藏推广”折叠的卡片也不显示。

编辑中的保护：

- 卡片里有未保存的输入时，点“关闭”、按 Esc、点击卡片外或点别的入口都不会关闭它，需要先保存或取消。
- 只查看，或进入编辑但没有实际修改时，可以直接关闭；修改后恢复原内容也视为没有未保存改动。
- 微博的信息流会复用同一个页面节点显示别的微博。节点换了作者时，没有未保存输入的卡片会自动关闭；有未保存输入的卡片会保留并停靠在窗口左下角，注明它属于哪个 UID，页面怎么滚动都能找到保存、取消和关闭；保存仍然写给打开卡片时的那位作者，冲突检查照常进行。在它保存或取消之前，不会打开别的卡片。
- 离开首页或“最新微博”、关闭这个选项、或登录账号变化时，入口和卡片会被移除，此时未保存的输入不会保留。
- 在工具箱或主页面板里保存、删除档案后，同一标签页信息流里对应作者的入口和卡片会随之更新；其他标签页的修改会在你打开卡片或开始编辑时读到。

### 微博计步器

可选 **记录网页版使用统计** 和 **在页面角落显示今日统计** 均默认关闭。

启用后可查看：

- 今日估算活跃时间；
- 今日已浏览的不同微博数量；
- 当前标签页的估算活跃时间和不同微博数量。

活跃时间要求页面可见、有焦点且最近有真实交互；60 秒无活动后暂停。帖子需要约 50% 可见并持续约 800 毫秒才计入，当天按稳定帖子 ID 去重。当前日结束后会丢弃具体 ID，只保留最多 90 天的每日活跃秒数和数量汇总。

统计仅保存在当前浏览器；不保存微博正文、作者浏览分析、媒体、滚动位置或逐条浏览时间线。可确认后清空当前账号的使用统计，不影响微博数据或其他 Toolkit 模块。

### 更新记录

从 v0.8.1 起，新版本可在首次符合条件的启动时显示一次当前版本的 **新功能**；用户主动关闭后，该版本不会反复弹出。Toolkit Home 的 **更新记录** 可随时重新打开从 v0.3.0 起有公开 tag 证据的版本说明。

全部内容随用户脚本内置，不从 GitHub 或其他服务器读取。旧版本不会依次自动弹出。

### 私信 Markdown 导出

在微博网页版私信中手动打开一个普通一对一会话后，使用会话界面的 **导出 Markdown**。Toolkit 会按顺序读取当前接口实际可访问的历史，并生成本地 `.md` 文件。

支持选择保存位置的浏览器会先显示保存对话框；取消时不发起历史请求、不生成文件。其他浏览器使用普通下载流程。

`WEIBO_PM_AI_3` 使用紧凑 A/B 对话格式，保留消息顺序、正文、源时间语义，以及图片、链接和不支持消息的标记。Toolkit 本身不调用 AI API。

范围限制：

- 只导出用户当前手动选择的普通一对一会话；
- 不自动遍历全部会话；
- 不支持群聊、服务/公共消息文件夹；
- 不下载媒体；
- 不恢复私信；
- 不发送、删除或撤回消息；
- 不主动修改未读状态；
- 接口没有返回、已删除、已撤回或不可访问的内容可能缺失。

导出文件是本地明文。虽然元数据不写入 A/B 与真实账号的映射、UID 或昵称，消息正文自身仍可能含有个人信息。把文件交给第三方服务属于用户与该服务之间的独立隐私边界。

## 数据与隐私

- 没有项目服务器、telemetry 或云同步。
- 关系雷达、粉丝快照、对应事件和友人档案按当前微博账号 UID 隔离，保存在用户脚本本地存储。
- 友人档案中的备注和标签是你手写的私人内容；备份文件是本地明文，包含这些内容，请自行妥善保管。
- 浏览体验偏好（包括是否在主页显示友人档案）、主页访问足迹、微博计步器和更新记录已读状态都是当前浏览器的环境数据，不进入备份。
- 自动更新设置、尝试/冷却时间、外观设置和移除协调标记同样不进入备份。
- 清除浏览器或用户脚本存储会删除或使本地数据不可访问。
- 工具不会在备份中保存登录凭据或请求认证信息。

## 备份与恢复

**导出备份**生成当前账号的本地 JSON 文件。支持的浏览器可显示原生“另存为”，否则由浏览器下载设置决定保存位置。

当前导出的是 Backup v3，包含：

- 关系雷达快照和事件；
- 粉丝快照和粉丝变化事件，或明确记录导出时不存在粉丝快照；
- 友人档案（手写备注与标签），或明确记录导出时不存在友人档案。

每个备份版本只覆盖它声明的模块，恢复时只替换这些模块：

| 备份版本 | 关系雷达 | 粉丝快照与粉丝变化 | 友人档案 |
|---|---|---|---|
| v1 | 替换 | 保持不变 | 保持不变 |
| v2 | 替换 | 替换 | 保持不变 |
| v3 | 替换 | 替换 | 替换 |

恢复前会完整验证文件中的全部模块，要求当前登录账号与备份 owner UID 一致，任何一部分缺失或无效都会在预览之前整体拒绝。预览会显示将被替换的范围，包括当前与备份中的友人档案数量，以及恢复后会被移除的当前档案数量。确认后完整替换备份覆盖的当前账号本地模块，不做合并。

旧 Backup v1、v2 仍可恢复，含义不变：它们不包含友人档案，恢复时不会删除或覆盖当前的友人档案。Backup v3 需要支持它的 Toolkit 版本才能恢复；较旧的版本会拒绝它而不是只恢复一部分。

确认恢复时会重新核对预览以来的变化：如果任一被覆盖的模块在预览之后被其他标签页修改，恢复会被拒绝或回退，不会覆盖那些较新的数据。恢复中途失败时，Toolkit 会说明实际结果——已全部回退、部分恢复，或最终状态无法确认——不会把这些情况报告为成功。

备份只包含上述数据，不包含登录凭据、请求认证信息、环境偏好、主页访问足迹或微博计步器数据。

普通原地升级兼容现有 v0.2.0–v0.9.5 本地状态，不需要仅为升级而恢复备份；升级后友人档案从空开始，原有数据不会被改写。跨浏览器、跨设备或卸载/重装前建议先导出。

## 已知限制

- API 可见关注数可能不同于微博显示总数。
- 关系变化发生在多页扫描期间时，可能出现一次短暂观察。
- 关系时间线只覆盖 Toolkit 实际观察并保存的事件。
- 粉丝快照可能被微博过滤；“消失”不揭示原因。
- 多标签页写入使用浏览器锁协调，但不是数据库级事务；浏览器无法安全协调时会失败或跳过，而不是静默覆盖。
- 友人档案只能在可从地址识别 UID 的 `/u/<UID>` 主页上新建；个性域名等其他形式的主页地址暂不支持。
- 友人档案中的昵称和关系信息只来自 Toolkit 已有的本地记录，不是实时状态；Toolkit 没有记录过的账号只显示 UID。
- 主页上的友人档案面板在离开该主页时关闭，尚未保存的输入不会保留。
- 信息流中的友人档案只支持首页和原生“最新微博”；搜索结果、评论区、私信、个人主页里的微博列表和转发内层作者都不显示入口。
- 信息流入口依赖微博当前的卡片结构；结构变化导致作者无法被证明时，入口会消失而不是猜测。信息流里的昵称提示在关系雷达或粉丝快照更新后，要到关闭工具箱面板、打开卡片或重新进入信息流时才会刷新。
- 切换微博账号后，应刷新页面再使用 Toolkit。
- 关系雷达单次最多 100 个请求；达到上限时不保存不完整结果。按每页 20 条估算约为 2,000 条可见记录，但这不是精确账号规模上限。
- 粉丝快照单次最多读取 100 个非空页，并可额外发送 1 个终止验证请求；达到安全上限时不保存结果。
- 私信导出只代表导出时接口实际返回的当前会话可访问历史。
- 移除粉丝会修改真实关系，无法自动撤销或重放。

## 开发与测试

生产源码按固定顺序拆分为连续片段：

```text
src/
```

生成并提交的可安装产物仍是单一文件：

```text
weibo-toolkit.user.js
```

源码拆分只改变开发时的文件组织，不改变 Weibo Toolkit 的运行行为、数据语义或用户安装方式。

检查源码片段与已提交产物是否逐字节一致：

```text
node scripts/build-userscript.mjs --check
```

从源码片段重新生成产物：

```text
node scripts/build-userscript.mjs --write
```

仓库提供一组小型公开核心不变量测试，直接从实际 userscript 源码加载并调用产品函数，不复制产品算法：

```text
node tests/run.js
```

公开测试命令会先执行构建一致性检查，再运行 `tests/` 下全部 `*.test.js`。其中友人档案的四组测试（数据与并发、Backup v3、主页面板与管理界面、信息流入口与卡片）通过 `tests/friend-notes-fixture.js` 提供的共享存储、页面锁和小型 DOM 模拟多个标签页，被测代码始终是生成的 userscript 本身。它们不访问网络，也不能代替真实登录环境下的浏览器验证。

信息流测试使用合成卡片结构，并纳入用户从真实页面提供的纯转发 `usercard` 昵称节点；它们不能证明所有真实微博布局或浏览器均已覆盖。新功能已根据用户实际网页试用反馈调整位置和交互，完整的跨浏览器验证仍有待继续。

友人档案的源码集中在 `src/085-friend-notes.js`，信息流部分在 `src/086-feed-friend-notes.js`，并接入 `src/040-page-profile-changelog.js` 里已有的信息流协调器；备份格式的扩展位于 `src/090-backup-export-auto.js` 和 `src/100-restore-export.js`。新增源码片段需要同时加入 `scripts/build-userscript.mjs` 的清单。

`weibo-toolkit.user.js` 会继续有意保存在仓库中，因为 Greasy Fork 直接使用它，用户也可以直接安装它，发布验证还要求生成源码与已提交产物完全一致。

维护者还使用更完整的本地回归工具；这些 exhaustive harnesses 和浏览器考古 fixture 不作为公共仓库的一部分。公开测试用于证明关键语义与安全声明，不替代完整发布验证。

项目没有 npm 依赖，不需要 Jest、Vitest 或 Mocha。当前版本仍以生成并提交的 userscript 作为对外发布事实来源。

## English summary

Weibo Toolkit is a local-first userscript for desktop web Weibo. It provides relationship-change tracking, API-visible follower snapshots and local hygiene tools, bounded follower removal, current-conversation Markdown export, hand-written private notes and tags bound to stable UIDs (Friend Notes, covered by Backup v3), and optional page/profile/usage enhancements. The UI is Chinese-focused. Most data stays in userscript-local browser storage; there is no project telemetry or cloud service. Mobile Safari and iPhone/iPad Weibo web are not currently supported.
